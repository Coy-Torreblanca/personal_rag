# Database Migration Cheat Sheet

## 🚀 Quick Start

```bash
# Always work from database package
cd packages/database

# Activate virtual environment (if using)
source .venv/bin/activate
```

## 📋 Daily Commands

### Check Status
```bash
alembic current      # What version is deployed?
alembic history      # See all migrations
alembic heads        # Latest migration versions
```

### Make Changes
```bash
# 1. Edit models in src/models.py
# 2. Generate migration
alembic revision --autogenerate -m "Description"

# 3. Apply
alembic upgrade head
```

### Rollback
```bash
alembic downgrade -1     # Undo last migration
alembic downgrade base   # Remove all tables (DANGER!)
```

## 🔧 Common Operations

### Add Table/Column
1. Add to `src/models.py`
2. `alembic revision --autogenerate -m "Add X"`
3. `alembic upgrade head`

### Rename Column
1. Update field name in `models.py`
2. `alembic revision --autogenerate -m "Rename X to Y"`
3. `alembic upgrade head`

### Add Index
```python
# In models.py, add to __table_args__
__table_args__ = (
    Index('idx_table_column', 'column_name'),
)
```

## ⚠️ Important Notes

### Do's
- ✅ Review autogenerated migrations
- ✅ Test downgrades
- ✅ Use descriptive migration names
- ✅ Commit migration files to git

### Don'ts
- ❌ Edit applied migration files
- ❌ Skip migration versions
- ❌ Run `DROP` without `downgrade()` logic
- ❌ Forget to run migrations in production

## 🐛 Troubleshooting

### "Target database is not up to date"
```bash
alembic current          # Check what's applied
alembic upgrade head     # Apply missing migrations
# OR if migrations are broken:
alembic stamp head       # Mark as up-to-date (careful!)
```

### "No changes detected"
- Check `alembic/env.py` imports
- Verify models are table=True
- Ensure database connection works

### Foreign key errors
- May need to reorder migration manually
- Create tables first, then add foreign keys

## 🐳 Docker/Podman

### Run migrations in container
```bash
# From API/worker container
cd /packages/database
alembic upgrade head
```

### Reset database (development)
```bash
# Stop containers
make dev-down

# Remove volumes
podman volume rm 30ai_postgres_data

# Restart
make dev-up

# Run migrations
cd packages/database
alembic upgrade head
```

## 📁 File Locations

- **Models**: `src/models.py`
- **Migrations**: `alembic/versions/*.py`
- **Config**: `alembic.ini`
- **Environment**: `alembic/env.py`

## 🆘 Emergency Recovery

### Migration failed halfway
```bash
# Check what was applied
alembic current

# Try to fix migration file, then:
alembic upgrade head --sql  # Preview
alembic upgrade head        # Apply
```

### Need to revert badly
```bash
# Rollback step by step
alembic downgrade -1
alembic downgrade -1
# etc.

# Or go back to specific version
alembic downgrade <version_id>
```

## 📞 Remember

1. **Models are source of truth** - Edit `models.py`, not raw SQL
2. **Migrations are one-way** - Applied migrations should never change
3. **Test locally first** - Always test migrations before production
4. **Backup production** - Before major schema changes
